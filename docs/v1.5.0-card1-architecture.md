# v1.5.0 Card 1：人脸几何（FaceGeometry）架构决策记录

> 状态：已落地（代码在 `ShiGuangKit/Sources/FaceGeometry`、`ShiGuangKit/Sources/AICore`、
> `FaceML/`、`App/`）。本文件记录**为什么这样分层**——每条决策对应代码注释里
> 的引用来源，评论先于文档的争议以本文为准。

## 背景

液化变形（Card 2）需要一张**可靠的人脸网格**做护栏：效果只应落在面部区域。
两条检测轨：

| 轨 | Provider | 槽位 | 虹膜 | 位姿 | 许可 |
|----|----------|------|------|------|------|
| 主路径 | `MediaPipeFaceMeshProvider`（FaceML 包） | 468 全网格（coverage 1.0） | 10 点 | Horn 四元数（roll/pitch/yaw） | Apache-2.0 |
| 兜底 | `VisionLandmarksProvider`（AICore） | 152 外壳槽位（coverage ≈0.32） | 无 | 仅 roll（双眼连线，置信 0.5） | 系统框架 |

## ADR-1：FaceML 是独立本地包，不进 ShiGuangKit 包图

**决策**：MediaPipe Provider 隔离在 `FaceML/`（platforms iOS 27.0），只被 App 依赖。

**理由**：`MediaPipeTasksVision` 是 **iOS-only 二进制框架**（xcframework 双切片
ios-arm64 + ios-arm64-simulator）。若作为 target 进 ShiGuangKit 包图，macOS 宿主上的
`swift test`（ci.yml Job 1：构建整个包图跑纯逻辑单测，ADR-007）会在**包解析阶段**失败
——二进制 target 的平台约束与 macOS 宿主冲突。隔离后 ShiGuangKit 保持
「macOS 可完整构建测试」不变。

**代价**：App target 多一个包依赖（project.yml 显式引入）；FaceML 与 AICore 之间
只能走协议（`FaceGeometryProviding`），不能共享文件私有细节——这正是想要的方向。

**上游约束**：mediapipe 上游 `Package.swift` 无版本 tag、checksum 随 master 滚动，
下游只能 `branch: "master"` 引用（NOTICE.md 已记录当前 zip sha256 取证）。

## ADR-2：协议签名用 `SendableSegmentImage` 装箱，不收裸 CIImage

**决策**：`FaceGeometryProviding.detect(_ image: SendableSegmentImage)`。

**理由**：`CIImage` 不可变但非 Sendable，Swift 6 strict concurrency 下跨 actor
传裸 CIImage 必然编译错误。复用 `PortraitSegmentation` 既有的
`@unchecked Sendable` 装箱（CIImage 不可变 ⇒ 装箱成立，同 PersonMaskProviding 论证）。

**代价**：调用方多一层 `SendableSegmentImage(CIImage(cgImage:))` 桥接；
换来两条 Provider 轨签名完全一致、注册表可用 `any FaceGeometryProviding & Sendable`
存在类型。

## ADR-3：注册表不变量——Vision 兜底轨常驻不可注销，主路径可热替换

**决策**：`FaceGeometryRegistry.init` 即注册 Vision 为主路径；`unregister` 拒绝移除
Vision 轨；`register(asPrimary: true)` 可热顶替。

**理由**：不存在「没有提供方」的状态——MediaPipe 模型加载失败（磁盘缺文件 /
框架不可用）时，无脸照片的液化护栏（Card 2）仍有 152 槽位可用。App 启动期
`warmUp()` 成功才注册 MediaPipe；失败静默留在兜底轨（日志留证）。

**并发**：`NSLock` 保护字典与主路径 ID（PerfSignpost / AlphaMemo 惯例）；
`detect` 在锁外调用（异步推理不持锁）。

## ADR-4：槽位契约——468 MediaPipe 规范槽位、图像归一化左上原点

**决策**：`FaceGeometry.landmarks` 恒 468 个槽位，索引 = MediaPipe Face Mesh 规范
槽位号；坐标 = 图像归一化、左上原点、x 右 y 下；`z` 为相对深度（2D 来源填 0）；
`confidence == 0` 表示该槽位未实测（消费者按 `slotCoverage` 判断可用性）。

**理由**：MediaPipe normalized landmark 与此约定逐字一致（主路径零变换）；
Vision 兜底轨经 `LandmarkSlotMap` 把各区域折线按**弧长**重采样到槽位序列
（点数相同恒等直通，防 lerp ulp 漂移）。Card 2 的液化护栏与网格叠加都依赖此契约。

**为什么 MediaPipe 拓扑表要逐字转写**：兜底轨需要「各区域 → 槽位序列」的映射表
（`FaceMeshTopology`），数据源是 MediaPipe 官方
`face_mesh_connections.py`（master，2026-10-24 取）——自造槽位号会与主路径输出
错位，两条轨的同一槽位必须指向同一解剖位置。

## ADR-5：位姿解算共享同一套 Horn 解算，符号由合成旋转单测钉死

**决策**：两条 Provider 轨的 roll/pitch/yaw 都走 `HeadPoseSolver`（Horn 1987
四元数，3D 锚点解算）；Vision 2D 轨只解 roll、pitch/yaw 置 0 且置信折半。

**踩坑记录**（测试锁死，不是口头约定）：互协方差矩阵方向写反（喂 Mᵀ）会**静默**
解出 Rᵀ——所有姿态角符号全反、无任何报错。现由合成旋转单测
（构造已知 R = Ry(yaw)·Rx(pitch)·Rz(roll) 断言恢复）锁定；
Euler 往返容差 1e-6（Float32 量化极限，非 1e-9）。

## ADR-6：演示人脸图用 NASA 公有领域照片

**决策**：`App/Assets.xcassets/DemoFace`（512×512，NASA 公有领域，
scikit-image `astronaut` 分发），sha256
`2418889d0d83962d51facc3832b55cf1849690018a1e873d1c551146555cd02f`。

**理由**：CI 截图验收需要「同一张图两条轨都有脸可检」的确定样本。该图经
**同一个 `face_landmarker.task` 模型**本地验证：478 点全部检出、锚点 sane
（slot 33 右眼外角 / 263 左眼外角 / 1 鼻尖 / 152 下巴 / 10 额顶位置合理）。
沙盒网络白名单只放行 Google/GitHub/PyPI，Wikimedia/Openverse 不可达——
选 PyPI 可取的 NASA 公版图，许可无争议（合规红线：禁版权素材）。
